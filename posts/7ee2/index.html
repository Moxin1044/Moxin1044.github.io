【ArchLinux】休眠唤醒后 Wi-Fi 掉线与 GNOME 锁屏无密码框的排查与修复

发表于2026-11-02|更新于2026-11-02|LinuxArchLinux系统
|总字数:3.1k|阅读时长:11分钟|浏览量:

前言

合上盖子，再打开，右上角的 Wi-Fi 图标还在，点开却是一片空白。过一会儿网络自己回来，也可能一直不回来。另一件更让人难受的事是，锁屏界面只显示壁纸和时钟，密码输入框不见了，只能盲按回车或者强行重启。

这两种现象出现在同一台机器上，看起来像两个问题，实际分别落在 PCIe 电源管理和 GNOME 登录认证两条链路上。本文记录排查过程、已经做的修改、验证方法和回滚方式。

测试机器：

项目 值
机器 ALLDOCUBE iWork GT Ultra
平台 Intel Meteor Lake
系统 Arch Linux，GNOME 51.1 / GDM 51.1.1，Wayland
内核 7.2.14-arch1-1
无线网卡 Realtek RTL8852BE，驱动 rtw89_8852be
睡眠方式 s2idle

现象

Wi-Fi 的问题有几个共同点：

  • 熄屏或挂起后唤醒，Wi-Fi 有时直接掉线，NetworkManager 里设备变成 unavailable；
  • GNOME 右上角的 Wi-Fi 列表为空，点不开任何网络；
  • 有时等十几秒会自己恢复，有时只能重启 NetworkManager 或重启系统；
  • 用网线、USB 网卡都不受影响，问题只出现在这块 RTL8852BE 上。

锁屏的问题更随机：

  • 唤醒后只看到背景和时钟，没有密码输入框；
  • 动一下鼠标、按几下键盘，偶尔能恢复，偶尔一直不出现；
  • 不是每次锁屏都复现，和 Wi-Fi 是否掉线没有严格对应关系。

Wi-Fi：PCIe 链路没有回来

日志

先看内核日志。问题发生时，几个关键错误会连在一起出现：

这几行日志对应的顺序是：

  1. 0000:00:06.0 是 Wi-Fi 卡所在的 PCIe 根端口。系统从 s2idle 唤醒时，根端口在 100 ms 内没有进入 Data Link Layer Active 状态。
  2. 链路没起来，rtw89_8852be 访问网卡寄存器就会超时，failed to write DBI register 和 xtal si not ready 都是这个阶段的表现。
  3. 驱动初始化失败，返回 -110，设备进入不可用状态。
  4. NetworkManager 拿不到可用接口，wpa_supplicant 无法绑定，GNOME 自然也无法扫描，Wi-Fi 列表就是空的。

这里有一个容易误判的地方：桌面上看到的是 Wi-Fi 掉线，但 Wi-Fi 省电策略只是诱因之一，根因在 PCIe 链路训练和根端口电源管理。只改 Wi-Fi 省电，可能让问题少出现几次，不能保证不再出现。

这两个参数的作用不同：

  • pcie_port_pm=off 关闭 PCIe 端口的运行时电源管理，避免根端口在唤醒后无法重新建立链路。
  • pcie_aspm=off 全局关闭 PCIe ASPM，作为兜底。

代价也要说清楚：关闭 ASPM 后 PCIe 省电会变差，续航可能略有下降；pcie_port_pm=off 影响的不只是无线网卡，而是所有 PCIe 端口的运行时电源管理。它们是排障用的保守配置，不是所有机器都该长期开启。

  • journalctl -t rtw89-resume 有记录，但没有反复重试失败；
  • 内核日志里不再出现 Data Link Layer Link Active not set。

一次成功不代表稳定。建议连续做十次以上合盖、熄屏、手动挂起，分别记录成功次数和失败时的日志。只有多次唤醒都不再掉线，才能说这个问题基本解决。

锁屏

锁屏后唤醒，确认密码输入框正常显示。再测试这几种路径：

  • 手动 Super+L 锁屏后立即唤醒；
  • 熄屏后等待几分钟再唤醒；
  • 挂起后唤醒；
  • 插拔电源、切换电池供电后再锁屏。

如果某一种路径仍然不显示密码框，先看 journal 里有没有同一条 authServicesSSSDSwitchable.js 报错，再决定是否继续调整 GDM 配置。

还没解决的问题

这套修改的目标是让机器可用，不是证明内核驱动没有 bug。还有几件事没有闭合：

  • pcie_aspm=off 和 pcie_port_pm=off 是全局关闭，续航和功耗会有代价，长期是否值得需要自己权衡；
  • 唤醒 hook 的 PCIe 链路重训练依赖具体根端口，换机器不能照抄地址；
  • 当前睡眠方式是 s2idle，可以尝试 mem_sleep_default=deep 切到 S3，但部分 Intel 平台对 S3 支持不完整，测试前保存工作；
  • 如果更新 BIOS 或内核后问题仍然存在，应该把 journalctl -b -k、lspci -vv -s 00:06.0、lspci -vv -s 01:00.0 一起反馈给 linux-wireless 和 rtw89 维护者；
  • 写这篇文章时，Wi-Fi 和锁屏都还需要更多次唤醒验证，当前只能确认参数已经生效，不能承诺彻底不再复现。

如果你也遇到类似现象，建议按“先确认 PCI 地址，再关省电，再加驱动参数，再加内核参数，最后才上唤醒 hook”的顺序做。每加一层就单独测试，出问题时才能知道是哪一层带来的变化。
