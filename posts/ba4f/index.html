【ArchLinux】ToDesk 在 GNOME Wayland 下屏幕共享授权框一闪而过：原因与修复

发表于2026-11-03|更新于2026-11-03|LinuxArchLinux桌面
|总字数:2.2k|阅读时长:8分钟|浏览量:

前言

同一台 Arch Linux 机器上，向日葵发起远程连接时，GNOME 的屏幕共享授权框会正常停住，点一下“共享”就能连。换 ToDesk，授权框只闪一下，大约两三百毫秒就没了，手还没来得及移到按钮上；有时远端黑屏，有时连接刚建立又退回去。

AUR 的 todesk-bin 安装时还会打印一句：

很容易顺着这句话得出“ToDesk 不支持 Wayland，只能切 X11”的结论。对 4.9.8.1 来说，这个结论不对。ToDesk 有 Wayland 抓屏实现，也能通过 PipeWire 出画面；授权框闪一下另有原因。

本文记录这台机器上的排查过程、日志证据、修复方法和回滚方式。

真正的原因

授权框被自动点掉了

GNOME 的屏幕共享对话框由 xdg-desktop-portal-gnome 提供。这个对话框本身是 GTK4 应用，同时会通过 AT-SPI 无障碍总线暴露自己的控件树。ToDesk 的 WaylandSecureUiController 会做三件事：

  1. 连接 a11y 总线；
  2. 在控件树里找到 portal 对话框；
  3. 选中显示器，模拟点击“共享”按钮。

ToDesk 日志里能看到完整过程：

从对话框出现到被点掉，大约 200 到 400 毫秒。桌面上看到的就是“闪一下”。向日葵不做这个自动点击，所以它的授权框会停在那里，等用户自己确认。

这也解释了一个看起来矛盾的现象：ToDesk 能抓屏，但用户没有机会授权。自动点击替用户做了决定，日志里的 accepted=true 和 action=click 就是这一步。

另一个问题：Session creation inhibited

自动点击只是第一层。实际使用还会遇到连接反复重试、对话框反复闪、画面起不来的情况。xdg-desktop-portal-gnome 的 journal 里会出现：

ToDesk 在重连时会重复创建 ScreenCast session。旧 session 没有清理干净时，mutter 51 会拒绝新 session，于是链路变成：

  1. 对话框弹出；
  2. ToDesk 自动点“共享”；
  3. portal 创建 session 失败，报 Session creation inhibited；
  4. 对话框关闭或客户端回滚；
  5. ToDesk 重试，回到第 1 步。

这是 ToDesk 的会话生命周期问题，和“支不支持 Wayland”是两件事。关掉自动点击能让授权框停下来，但不能保证旧 session 一定被清理干净，所以后面还要单独看这个错误。

修复：让 portal 对话框不被自动点

原理

ToDesk 是 AT-SPI 的客户端，portal 对话框是 GTK4 应用。只要让 xdg-desktop-portal-gnome 不把对话框注册到无障碍总线，ToDesk 的自动化就找不到按钮，也就点不掉。

GTK4 用环境变量 GTK_A11Y 控制无障碍桥接：

  • GTK_A11Y=atspi：启用，默认值；
  • GTK_A11Y=none：关闭。

只给 xdg-desktop-portal-gnome.service 加一个 systemd user drop-in，不修改全局环境。

操作

确认配置生效

期望结果：

如果 Environment 里没有 GTK_A11Y=none，先确认 drop-in 文件名以 .conf 结尾，再执行一次 daemon-reload 和 restart。只看 is-active 为 active 不够，那只说明服务在跑，不说明环境变量进去了。

测试

  1. 打开 ToDesk，发起远程连接；
  2. 这次 GNOME 的“共享屏幕”对话框应该会停住；
  3. 选中显示器，点“共享”或“Share”；
  4. 远端应该能正常出画面。

ToDesk 对 portal 的响应有超时，授权框停住后不要放太久。先点显示器，再点共享，动作快一点。

回滚

这个修改只影响 xdg-desktop-portal-gnome 这一个进程的无障碍桥接，不会全局关闭无障碍。其他 GTK 应用不受影响。

如果你使用 Orca 等读屏软件，并且需要读屏来操作这个授权框，应该回滚。这个 workaround 的目的就是让授权框停下来等人工确认，代价是 portal 对话框本身不再向读屏软件暴露控件。

适用范围和注意事项

这个方案是 GNOME 专用的。换到 KDE 或 Hyprland，负责 ScreenCast 的 portal 后端会变成 xdg-desktop-portal-kde 或 xdg-desktop-portal-hyprland，drop-in 的服务名要相应替换。

GTK_A11Y=none 只关闭该 portal 进程的无障碍桥接，不是全局关闭无障碍。它是针对这次自动点击的定点处理，不是所有 GTK 程序都适用的通用开关。

授权框需要手动点，这是修复的目的。ToDesk 有超时，动作要快。

Session creation inhibited 仍可能出现。那是 ToDesk 重连时旧 ScreenCast session 没有清干净的问题，本方案解决不了。遇到时重连客户端或重启 todeskd.service。

从日志看，ToDesk 原本会在用户没有确认的情况下通过 AT-SPI 模拟点击“共享”，这相当于绕过了 GNOME 的屏幕共享同意机制。这个行为不理想，值得向 ToDesk 反馈。本文的 drop-in 只是把这一步挡住，让授权回到用户手里。

升级 ToDesk 后要复查。如果后续版本修掉了自动点击，这个 workaround 可以撤掉；如果 ToDesk 改了 portal 交互方式，也要重新看日志，不要默认旧配置一直有效。

写这篇文章时，修复只在这台 Arch Linux + GNOME 51.1 的机器上验证过。其他发行版、其他 GNOME 版本、其他 portal 后端的表现可能不同。遇到问题先把 GTK_A11Y、portal journal 和 ToDesk session 日志三样都取下来，再判断是哪一层。
