【漏洞复现】CVE-2026-60004 Gitea diffpatch 接口 Git 钩子注入致远程命令执行

发表于2026-10-14|更新于2026-10-14|漏洞Web分析复现
|总字数:1.7k|阅读时长:7分钟|浏览量:

前言

Gitea 在 1.17 ~ 1.27.0 版本中存在一个严重的代码注入漏洞（CVE-2026-60004，GHSA-rcr6-4jqh-j84m），官方已在 1.27.1 修复。漏洞位于 diffpatch（差异补丁）API：攻击者只需拥有一个账号并对任意仓库具备写权限，即可通过该接口提交恶意补丁，在服务器以 裸仓库（bare repo） 形式存储的临时仓库中 植入并执行 Git 钩子，从而以 Gitea 服务账户权限执行任意命令。

由于 Gitea 默认 开放注册，外部人员可以自行注册账号并创建仓库，从「无任何权限」直接获得仓库写权限，使该漏洞极易被真实利用（CVSS 9.8）。

漏洞信息

  • 漏洞编号：CVE-2026-60004（GHSA-rcr6-4jqh-j84m）
  • 影响版本：Gitea 1.17 ~ 1.27.0
  • 修复版本：1.27.1
  • 漏洞位置：POST /api/v1/repos/{owner}/{repo}/diffpatch
  • 利用前提：拥有账号 + 对目标仓库具备写权限（默认开放注册时，攻击者可自行注册并创建仓库，天然满足）
  • 危害：任意命令执行（以 Gitea 运行账户身份，CWE-94）

环境信息

  • 目标：一台存在该漏洞的 Gitea 实例（受影响的 1.27.0）
  • 服务账户：git（Run As Username: git）
  • Git 版本：2.54.0（git apply -3 需要 Git ≥ 2.32）

漏洞原理

diffpatch 接口

Gitea 提供 diffpatch 接口，用于对一个仓库应用一段 unified diff 补丁：

服务端逻辑位于 services/repository/files/patch.go，流程为：创建临时仓库 → 克隆目标仓库 → git apply 应用补丁 → 生成提交 → 推送回目标仓库。

漏洞点：裸仓库 + git apply --index --cached + three-way 回退

关键点：

  1. 临时仓库是 裸仓库，其「工作目录」就是 Git 目录本身（$GIT_DIR）；
  2. 正常情况下 --cached 只写索引，不会写工作区。但 把同一个补丁提交两次 会产生 add/add 冲突，触发 Git 的 three-way 回退（-3）——即使带 --cached，Git 仍会把索引中的路径 checkout 到工作区；
  3. 于是补丁里的文件被真实地写进裸仓库的 Git 目录：hooks/post-index-change 成为一个「活的」Git 钩子；
  4. post-index-change 是 Git 在 写索引时 调用的钩子（git apply、read-tree、update-index 等都会触发），因此 无需等待 push，diffpatch 操作本身就会执行该钩子；钩子以 Gitea 服务账户（git）权限运行，实现任意命令执行。

结果回显（无外连）

临时仓库是 --shared 克隆，其 objects/info/alternates 指向 源仓库（真实仓库） 的对象目录。钩子可以据此定位真实仓库的 Git 目录，把命令输出写成对象并 update-ref 创建一个分支；攻击者再用 smart HTTP 拉取该分支即可读取命令输出，全程不需要目标主动出网。

官方修复

1.27.1 通过 PR #38637 修复：把临时仓库改为 非裸仓库（non-bare） 克隆，使工作区与 Git 目录分离，补丁再也无法写入 hooks/ 等 Git 内部文件。

修复建议

  1. 升级：立即升级到 Gitea 1.27.1 及以上；
  2. 关闭开放注册：DISABLE_REGISTRATION = true，或改为管理员审批 / 邮箱域名白名单；
  3. 收紧接口权限：限制 diffpatch 等会写仓库内容 / Git 目录的接口，仅授予可信用户并做审计；
  4. 资产排查：检查仓库中是否存在异常的 hooks/、custom_hooks/ 文件（可执行脚本），以及来源不明的分支；
  5. 最小权限：以低权限、隔离的账户运行 Gitea，降低 RCE 后的影响面。
